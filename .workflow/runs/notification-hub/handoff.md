## Key decisions (see `plan.md`'s Autocrítica for full reasoning)

- **Scheduling:** a Kubernetes `CronJob` (hourly, `schedule: "0 * * * *"`) invoking `python -m app.jobs.notification_check` on the existing backend image — mirrors the repo's own existing `k8s/mysql-backup-cronjob.yaml`/`backend-migration-job.yaml` precedents. No in-process APScheduler (backend runs 2 replicas in one of the two live manifest sets — an in-process scheduler would double-fire) and no Celery/broker (unjustified for three simple daily checks). Hourly rather than once-daily cadence is a zero-code-complexity robustness fix for missed runs — the trigger query itself only ever matches "today," so this doesn't reintroduce backfill risk (NH-07).
- **Push:** standard Web Push protocol + VAPID via `pywebpush` (verified current: v2.3.0, actively published, supports VAPID natively), not Firebase Cloud Messaging — no native app exists to justify FCM's overhead/vendor lock-in.
- **PWA shell:** hand-written, minimal `public/manifest.json` + `public/sw.js` (push listener only, no offline caching) — no new npm dependency (`vite-plugin-pwa`/Workbox rejected as unneeded for this scope).
- **Data model:** `Notification` (frozen/pre-rendered `message`, non-FK `reference_id`, idempotency via `UniqueConstraint(student_id, notification_type, reference_id)` — the NH-06 "exactly once, ever" guarantee) and `PushSubscription` (no uniqueness on `endpoint`, per NH-02's explicit no-dedup requirement).
- **Opt-in identification:** reuses the `authenticate_student`(registration_number+pin) idiom from `pre_checkin_service.py`/`medical_exam_service.py`, but — per NH-01's explicit, reviewed acceptance criteria — returns a real 401 with a clear message on invalid credentials, a deliberate divergence from those two files' anti-enumeration "generic accepted" pattern. Mitigated with the same `RateLimiter` idiom already used everywhere else in this codebase for public credential-bearing endpoints.
