## Key Decisions

- Corrected delivery order: Pré-Checkin → Medical/Documents → Financial Foundation → Contracts → Reports.
- Pré-checkin is distinct from attendance; physical check-in remains the official attendance event.
- Phase 1 decisions resolved: eligibility is configurable per class/event via minimum belt (general classes: none; yudansha: blue+; graduated: purple+); changes lock one hour before event start; public endpoint uses registration+PIN with IP/registration rate limiting and generic responses; pre-checkin never auto-converts to attendance — only a physical check-in does, preserving its physical method.
- During PR-1 verification, fixed a latent bug where `app/main.py` bootstrapped schema via `create_all` instead of Alembic, making the initial revision a no-op on a fresh database; Alembic is now the single source of schema truth.
- **Phase 2 (Documents) decisions resolved (2026-07-19):** documents stored in OCI Object Storage (reusing `dojo-infra/terraform/modules/storage/`), backend keeps only metadata + object key; uploads limited to PDF/JPEG/PNG up to 10MB; expired or orphaned (student removed) documents are soft-deleted with an audit trail (who/when), never hard-deleted automatically. Access is instructor/admin by default, **except medical-exam uploads specifically**, which also allow student self-service via a public registration+PIN endpoint (decided during Phase 2 planning — see "Requirements Review — Phase 2" below).
- **Phase 3 (Finance) decisions signed off (2026-07-20):** pricing uses fixed plans by weekly-frequency tier (D9) using declared `Student.classes_per_week` field (D1 confirmed); billing is monthly with a single standardized due date for all students and proportional charging in the enrollment month; overdue payments are flagged in reports/dashboards only (D8); partial/overpayments tracked as residual balance applied next (D7); no discounts or scholarships modeled (D10 confirmed); medical-exam status is display-only on overdue dashboard, gating nothing (D3 confirmed, narrowing Phase 2's "renewal/billing action" language); student prices locked to assigned `PlanVersion` (D11 confirmed, grandfathered), changed only via explicit reassignment — in practice triggered during annual contract renewal (Phase 4 responsibility; see plan.md Phase 3 section for integration breadcrumb).
- **Phase 4 (Contracts) decisions resolved (2026-07-19):** the legal template is versioned, and each generated contract records which template version and which financial plan/version it used; signature capture supports both an on-screen/touch signature (embedded into the generated PDF, tablet flow) and upload of an externally-signed PDF (via the Phase 2 document policy) — the operator chooses per contract.
- **Phase 5 (Reports) decisions resolved (2026-07-19):** REP-04's financial projection is the simple model — expected revenue over the next N months (default 3) assumed as the sum of currently active plans, with no adjustment for historical delinquency/cancellation.

## All 3 known e2e failures fixed and confirmed via real CI (2026-07-22)

Root-caused and fixed both bugs the previous session left open, each confirmed against real CI (not local — this machine's Docker Desktop/WSL2 setup has its own unrelated networking flakiness that made local reproduction unreliable; see below):

1. **PDF success-message timeout — real frontend bug, not a UI-timing issue as suspected.** `MedicalExamPage.tsx` did `response.data.message || <Portuguese fallback>`. The public endpoint *always* returns a non-empty generic message by design (Phase 1's "never disclose credential validity" pattern), so the Portuguese fallback the test's `/sucesso|registrado/i` regex expects was unreachable dead code — the backend's English generic text was shown instead. Fixed by always showing the fixed Portuguese message, ignoring the response body. Commit `6c0ca0e`.
2. **JPEG/PNG 400s — the "Cypress `selectFile()` Content-Type quirk" hypothesis from the prior session was wrong.** Captured the real outgoing browser request via `cy.intercept` and confirmed the `Content-Type: image/jpeg`/`image/png` headers and magic bytes were correctly formed. The actual cause: `cy.intercept()` itself decodes/re-encodes intercepted request bodies as UTF-8 text before forwarding, which corrupts binary multipart content — byte sequences that aren't valid UTF-8 (the JPEG/PNG magic bytes) become replacement characters on the wire, so the backend's magic-byte check correctly rejects the now-corrupted upload with 400. The PDF test was unaffected only because its content is pure ASCII, which round-trips through UTF-8 unchanged. Fixed by removing the `cy.intercept()`/`cy.wait()` pattern for the JPEG/PNG tests and verifying success via the UI message instead (same pattern the PDF test already used for its own check). Commit `a3ff305`.
3. **Bonus: a masked CI config bug.** Once both real bugs were fixed, the `e2e` job still went red — `actions/setup-python`'s post-job cache-save step failed because nothing in that job actually runs `pip` (docker compose builds the backend in its own container), so the expected cache directory never existed. This was previously hidden because the job always failed for a real reason first. Removed the unused Python setup step. Commit `0254e3c`.

**Confirmed via real CI, run [29915208590](https://github.com/gregori/dojo-full/actions/runs/29915208590): 25/25 Cypress tests passing, `e2e` job green.**

**Local sandbox note (this session, Windows):** reproducing this locally hit three unrelated, real environment issues on this machine, now fixed/cleaned up where safe to do so: (a) `entrypoint.sh` gets corrupted to CRLF on checkout (`core.autocrlf=true`), breaking Docker's shebang — fixed by adding `.gitattributes` (`*.sh text eol=lf`), commit `6c0ca0e`; (b) a stray host `.venv` (Windows-shaped, likely from a prior `uv run` invocation despite this backend being Poetry-based) was visible inside the container via the bind mount and broke `poetry run`, cleaned up (gitignored, not committed); (c) Docker Desktop's WSL2 port-forwarding intermittently corrupted some `localhost`-routed POST bodies — unfixable from our side, environment-specific to this machine, not present in real CI. Together these made local repro unreliable enough that the JPEG/PNG root cause was ultimately confirmed by iterating against real CI runs instead.

## Jest unit test suite added (2026-07-22)

Wrote the frontend's first Jest unit tests — greenfield, no existing pattern to follow. Established the convention: co-located `*.test.tsx` files, jsdom test environment, ts-jest transformed to CommonJS (`jest.config.cjs`, kept separate from Vite's ESM build config so it doesn't fight `"type": "module"`), and `jest.mock('../services/api', () => ({...}))` with an explicit factory for any test touching the API layer — required because `services/api.ts` uses `import.meta.env.VITE_API_URL`, which is Vite-only syntax that would fail to even compile under ts-jest's CommonJS transform if the real module were ever loaded (an explicit factory means Jest never does).

22 tests across 5 files: `useAuth` (JWT decode/login/logout/localStorage), `Toast` (fake-timer auto-dismiss), `MedicalExamBadge` (presentational), and full page-level tests for `LoginPage` and `MedicalExamPage` with the network layer mocked — the latter doubles as a regression test for the success-message fix in `6c0ca0e`. 95%+ statement coverage on all five files. Commit `38a8b79`.

Two real, separate issues surfaced and fixed along the way (both pre-existing, unrelated to the tests themselves):
- **React 19 + jsdom needs explicit setup**: `TextEncoder`/`TextDecoder` polyfills (react-router-dom needs them, jsdom doesn't provide them) and the `IS_REACT_ACT_ENVIRONMENT` global flag (React 19 no longer infers this automatically). Both added to `src/setupTests.ts`.
- **`LoginPage.tsx`'s `<label>`s aren't associated with their inputs** (no `for`/`id`) — a real, minor accessibility gap, left as-is (out of scope) but worked around in the test by querying `input[type="email"]`/`input[type="password"]` directly, matching the existing Cypress e2e test's own convention for this same page.
- **jsdom's file-input constraint validation doesn't understand MIME-type `accept` values** (only extension-based ones) — a jsdom limitation, not an app bug. It marks a correctly-attached file as invalid, silently blocking a real click-triggered submit. Standard testing-library workaround: dispatch `fireEvent.submit(form)` directly (wrapped in `act`) instead of clicking the button, for the tests that need the upload to actually go through.

**Bonus, unrelated to unit tests but found and fixed along the way:** `poetry.lock` was already committed (since PR-2) and correctly pins `greenlet` at a working version, but neither `Dockerfile.dev` nor `Dockerfile.prod` ever copied it into the build context — only `pyproject.toml` was. Every backend image build therefore silently re-resolved dependencies fresh against PyPI's live index instead of using the pinned lock. This caused a real, reproducible `e2e` CI failure (`greenlet` published a `3.5.4` release with no wheels yet for the build's Python/platform). Fixed by adding `poetry.lock` to both Dockerfiles' `COPY` line. Commit `4bc3f2f`. Confirmed both `CI - Frontend` and `CI - Backend` green after this fix, runs [29918206855](https://github.com/gregori/dojo-full/actions/runs/29918206855) / [29918206853](https://github.com/gregori/dojo-full/actions/runs/29918206853).
